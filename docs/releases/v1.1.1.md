# v1.1.1 — Browser Gateway PROPFIND checkpoint

## Status

Verified on the physical WD My Cloud Gen1 deployment.

## Verified changes

- Browser Gateway `webdav-gw` runs as a native static ARMv7 binary.
- Gateway listens on `127.0.0.1:6066` and proxies to WebDAV on TCP 6065.
- Browser directory `GET` rendering remains functional.
- WebDAV `PROPFIND` responses are filtered at the gateway to hide common internal entries such as Syncthing and macOS metadata files.
- Normal WebDAV entries remain visible after filtering.
- `FamilyPhotos` remains read-only through WebDAV.
- Samba remains independent of the WebDAV `FamilyPhotos` restriction and retains normal CRUD behavior according to filesystem permissions.
- Cloudflare Tunnel routes the public hostname to the Browser Gateway.
- The production ARMv7 binary and the build-machine binary were verified to have identical SHA-256 hashes.

## Permission model

The intended access model remains:

| Access path | Private roots | FamilyDocs | FamilyPhotos | FamilyShared | FamilyVideos |
|---|---|---|---|---|---|
| Samba | CRUD | CRUD | CRUD | CRUD | CRUD |
| WebDAV | CRUD | CRUD | Read only | CRUD | CRUD |
| Browser Gateway | WebDAV behavior | WebDAV behavior | WebDAV behavior | WebDAV behavior | WebDAV behavior |

The WebDAV restriction on `FamilyPhotos` must not be interpreted as a restriction on Samba.

## Security and privacy

No production passwords, API keys, tunnel credentials, private keys, personal family names, photos, or documents belong in this release documentation.

Public examples use only the generic aliases `Ayah`, `Ibu`, `Anak1`, `Anak2`, and `Anak3`.

## Rollback

The previously verified v1.1.0 gateway binary was retained on the physical deployment as a local rollback copy before the v1.1.1 replacement.

A release asset should contain only the distributable ARMv7 gateway binary and must not contain production configuration or credentials.
