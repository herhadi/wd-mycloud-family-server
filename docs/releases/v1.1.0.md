# v1.1.0 — Browser Gateway checkpoint

**Status:** Verified rollback checkpoint on the physical WD My Cloud Gen1.

## Included

- Direct per-user WebDAV roots.
- Family folders exposed inside each private root through bind mounts.
- `webdav-gw` lightweight static ARMv7 Browser Gateway.
- Browser directory `GET` rendered as human-friendly HTML.
- Basic Authentication passed from browser requests to WebDAV.
- `webdav-gw.service` enabled and running at boot.
- Gateway listens only on `127.0.0.1:6066`.
- WebDAV remains on `0.0.0.0:6065`.
- Cloudflare Tunnel routes the public hostname to `127.0.0.1:6066`.
- Cloudflare ingress configuration validates successfully using the WD-specific command syntax.

## Verified commands

Cloudflare configuration validation on the WD:

```bash
/usr/local/bin/cloudflared tunnel --config /root/.cloudflared/config.yml ingress validate
```

Expected result:

```text
Validating rules from /root/.cloudflared/config.yml
OK
```

Gateway service:

```bash
systemctl status webdav-gw --no-pager
```

Expected state:

```text
Active: active (running)
```

## Known issue for v1.1.1

The Browser Gateway hides common macOS/Syncthing internal files from its HTML listing, but WebDAV `PROPFIND` responses are currently passed through without filtering.

Windows WebDAV can therefore still display entries such as:

```text
.stfolder
.temp
.mace_*
.trashed-*
```

This is a presentation issue only. The files are not deleted or modified.

The planned fix is WebDAV `PROPFIND` response filtering in the gateway while preserving compatibility with Finder and other WebDAV clients.

## Safety boundary

- Do not expose TCP 445 publicly.
- Do not expose TCP 6066 directly.
- Keep `/etc/webdav/webdav.env` outside Git.
- Keep Cloudflare tunnel credentials outside Git.
- Use this checkpoint as the rollback point before the next gateway change.
