# Syncthing Photo Backup

## Purpose

Syncthing is used only for phone-photo backup into the Family Photos area. The intended flow is:

```text
Android phone
    │
    │ Send Only
    ▼
WD My Cloud
    │
    │ Receive Only
    ▼
/data/Family/Photos/<member>
```

Syncthing is not the user-facing file manager. Family members access the resulting photos through Samba or WebDAV, where `FamilyPhotos` is read-only.

## Naming and portability

The repository intentionally uses generic family-role labels:

- `Ayah`
- `Ibu`
- `Anak1`
- `Anak2`
- `Anak3`

These labels represent roles, not fixed personal names. Anyone deploying this project may map the roles to their own private family names or directory names in their local configuration. **Do not document those private names in this public repository.**

## Server prerequisites

Before configuring a phone:

- `/data` is mounted from `/dev/sda4`.
- `/data/Family/Photos/` exists.
- The corresponding member directory exists.
- The `syncthing` service is running.
- Syncthing GUI is reachable on the LAN at TCP 8384.
- The Syncthing folder is shared with the phone.
- The member photo directory is writable by the `syncthing` service account so Syncthing can create `.stfolder` and receive files.
- Samba/WebDAV users remain read-only for `FamilyPhotos`.

The actual local directory names are deployment-specific. Use the generic role name in this documentation and substitute the local private directory when performing setup.

## Configure Syncthing on Android

Use the Syncthing Android application installed on the phone. Exact UI wording can vary by Android client/version.

### 1. Add the phone photo folder

On the phone:

1. Open Syncthing.
2. Add or edit the folder containing the photos.
3. Select the real Android photo directory, such as the camera/photo directory used on that phone.
4. Give the folder a descriptive label, for example `Phone Photos`.
5. Share the folder with the WD My Cloud device.

Do not move or delete the original photos merely to configure Syncthing.

### 2. Set the phone folder to Send Only

Open the folder settings and choose:

```text
Folder Type: Send Only
```

Send Only means the phone publishes its local state and does not apply remote changes back to the phone. This is the intended mode for a reference/source photo folder.

### 3. Share with the WD My Cloud

The phone folder must be shared with the Syncthing device running on MyCloud. The server accepts the folder using the folder ID generated by Syncthing.

## Configure Syncthing on WD My Cloud

The Syncthing GUI runs on:

```text
http://<MYCLOUD-IP>:8384
```

The GUI is LAN-only and must not be exposed directly to the Internet.

### 1. Add the folder

In the MyCloud Syncthing GUI:

1. Add the shared folder from the phone, or edit the existing folder.
2. Set the local path to the corresponding private Family Photos directory.
3. Confirm the phone is listed as a shared device.
4. Save the configuration.

Example using the generic repository role:

```text
Label: Ayah - Phone Photos
Path: /data/Family/Photos/Ayah
```

When deploying for another family, replace `Ayah` with the desired role/name in the private configuration. Do not commit the private name to Git.

### 2. Set the MyCloud folder to Receive Only

After the folder is initialized and the phone is confirmed as the source, set the MyCloud folder type to:

```text
Folder Type: Receive Only
```

Receive Only accepts changes from the cluster but does not propagate local changes back to other devices. It is appropriate for a backup destination where local edits are not intended to become the source state.

This creates the intended one-way backup relationship:

```text
PHONE
Send Only
   │
   │ photos
   ▼
MYCLOUD
Receive Only
```

### 3. Do not edit Family Photos through Samba/WebDAV

The final permission model is:

```text
Phone / Syncthing  → writes photos
Family users       → read photos
```

Samba and WebDAV expose `FamilyPhotos` as read-only. This prevents accidental deletion or modification of the backup through normal file browsing.

## Adding another family phone

Repeat the same model for each role:

```text
Role    Destination
Ayah    /data/Family/Photos/Ayah
Ibu     /data/Family/Photos/Ibu
Anak1   /data/Family/Photos/Anak1
Anak2   /data/Family/Photos/Anak2
Anak3   /data/Family/Photos/Anak3
```

Each phone should have its own Syncthing folder and should be configured as **Send Only**. Each corresponding MyCloud folder should be configured as **Receive Only**.

## Verifying a sync

On the phone, wait until the folder reports that it is up to date.

On MyCloud, verify the live directory using the local role path:

```bash
find /data/Family/Photos/Ayah -type f | head
```

Check the total number of files:

```bash
find /data/Family/Photos/Ayah -type f | wc -l
```

Check disk usage:

```bash
du -sh /data/Family/Photos/Ayah
```

For another deployment, replace `Ayah` with the appropriate role directory. Do not commit private directory names to this repository.

## Folder marker and permission errors

Syncthing creates a `.stfolder` marker inside each sync folder. If the log reports:

```text
Failed to create folder marker ... permission denied
```

check the live folder ownership and permissions. The `syncthing` service account must be able to create files and directories there.

Example:

```bash
ls -ld /data/Family/Photos/Ayah
```

Expected ownership for a receive destination is typically the `syncthing` service account with the appropriate Family Photos group/permissions.

Do not create `.stfolder` manually.

## Receive Only local changes

Receive Only does not mean the filesystem becomes immutable. A local change can be detected as a local change that is not propagated. Syncthing provides a way to revert local changes back to the cluster state.

For this server, do not manually modify or delete files in the Family Photos directories. Use the phone/source side when a photo set needs to be changed.

## Recovery rule

If the server photo directory is empty or the Syncthing folder is recreated, do not delete the phone photos. First verify the phone still contains the source photos. Then re-share/reinitialize the Syncthing folder and allow the phone's Send Only folder to repopulate the MyCloud Receive Only destination.

If Syncthing reports `folder marker missing`, do not immediately reset the entire Syncthing database. First verify:

1. the configured path exists;
2. the path is the intended live `/data/Family/Photos/<member>` directory;
3. the `syncthing` service account can write there;
4. all filesystem mountpoints are already mounted;
5. the source phone still contains the photos.

A folder-specific database reset should be treated as a recovery operation rather than routine setup.

## Security

- Do not expose TCP 8384 to the public Internet.
- Do not commit Syncthing API keys to Git.
- Do not commit private device IDs together with private credentials.
- Never store phone photos or other family data in this repository.
- Keep the repository as configuration/documentation source-of-truth, not as a backup of `/data`.
